# VoicePrompter Transport Protocol (Draft)

> Status: Draft 0.2
>
> This document defines the transport protocol used by VoicePrompter to communicate with external applications.
>
> The protocol is transport-independent and may be used over WebSocket, MQTT, REST, files or future communication layers.

---

# Design Goals

- Simple
- Human readable
- JSON based
- Transport independent
- Versioned
- Backward compatible
- Easy to debug

---

# General Message Format

Every message consists of an envelope and a payload.

```json
{
    "protocolVersion": 1,

    "application": "VoicePrompter",
    "applicationVersion": "1.0.0",

    "messageId": "4f7a4d2b",

    "timestamp": "2026-08-02T21:14:32.154Z",

    "type": "CueDetected",

    "source": "speech",

    "payload": {}
}
```

---

# Envelope

## protocolVersion

Version of the transport protocol.

Applications communicating together must support the same protocol version.

---

## application

Application name.

Example

```json
"application": "VoicePrompter"
```

---

## applicationVersion

Application version.

Used only for diagnostics.

Example

```json
"applicationVersion": "1.0.0"
```

---

## messageId

Unique identifier generated by the sender.

It is used to correlate requests, responses and acknowledgements.

Example

```json
"messageId": "4f7a4d2b"
```

---

## timestamp

UTC timestamp generated by the sender.

Example

```json
"timestamp": "2026-08-02T21:14:32.154Z"
```

---

## source

Origin of the message.

Examples

```
speech
keyboard
mouse
click
transport
api
```

# CueDetected

Example

```json
{
    "protocolVersion": 1,

    "type": "CueDetected",

    "source": "speech",

    "payload": {

        "cueId": "c8d21",

        "cueIndex": 4,

        "modifiers": [
            "!"
        ],

        "tokens": [
            "PLAY",
            "VIDEO",
            "ID",
            "47"
        ],

        "raw": "PLAY VIDEO ID \"47\""
    }
}
```

---

## cueId

Unique identifier of a Cue.

Used to reference a specific Cue instance.

---

## cueIndex

Position of the Cue within the current document.

Useful for navigation commands such as:

```
GotoCue

NextCue

PreviousCue
```

---

# Command

Example

```json
{
    "protocolVersion": 1,

    "type": "Command",

    "source": "transport",

    "payload": {

        "command": "Continue",

        "replyTo": "4f7a4d2b"
    }
}
```

---

## replyTo

Optional reference to a previous message.

Typically used to acknowledge or continue processing after a Cue.

---

# RuntimeUpdate

Runtime information does not modify the original document.

Example

```json
{
    "protocolVersion": 1,

    "type": "RuntimeUpdate",

    "payload": {

        "cueId": "c8d21",

        "timeLeft": "00:01:24"
    }
}
```

---

# Hello

Optional handshake.

Example

```json
{
    "protocolVersion": 1,

    "type": "Hello",

    "application": "VoicePrompter",

    "applicationVersion": "1.0.0"
}
```

# Compatibility

Applications should reject communication if the protocol version is unsupported.

Application version should only be used for diagnostics.

---

# Philosophy

The protocol transfers information only.

It never interprets Cue commands.

Cue interpretation always belongs to external software.
